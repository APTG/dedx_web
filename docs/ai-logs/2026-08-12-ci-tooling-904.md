# 2026-08-12 — CI Tooling Fix (PR #904)

## Session Narrative

### Prompt 1: Check why PR #904 is failing CI and fix it

**AI response**: PR #904 is a dependabot PR bumping the `javascript-tooling`
group (10 devDependencies) in a single directory. The `Static Analysis
(format, lint, check)` job failed at `eslint .` with:

```
typescript-eslint does not support TS 7.0.
Please see https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#running-side-by-side-with-typescript-6.0
See also https://github.com/typescript-eslint/typescript-eslint/issues/10940
```

Of the 10 updates in the group, `typescript` was bumped `6.0.3` → `7.0.2`
(the new Go-based `tsgo` compiler, a major version bump). `typescript-eslint`
was also bumped, but only `8.65.0` → `8.66.0` — nowhere near a release that
supports TS 7, per the linked tracking issue.

**Fix**: pinned `typescript` back to `^6.0.3` in `package.json` while keeping
the other 9 updates from the group (eslint, jsdom, playwright, globals,
tailwind-variants, @types/node, @internationalized/date,
@testing-library/user-event, typescript-eslint), then regenerated
`pnpm-lock.yaml` with `pnpm install`. Added an `ignore` rule for
`typescript: >=7.0.0` to `.github/dependabot.yml` so the bot doesn't
re-propose the same incompatible major bump on its next daily run. Verified
locally: `pnpm run format:check`, `pnpm run lint`, `pnpm run check`, and
`pnpm test` all pass.
