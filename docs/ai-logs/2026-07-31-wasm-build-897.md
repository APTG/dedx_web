# 2026-07-31 — WASM Build Fix (PR #897)

## Session Narrative

### Prompt 1: Check why PR #897 is failing CI and fix it

**AI response**: PR #897 is a dependabot PR bumping the `libdedx` submodule
from `22e43a9` to `d5bf0cd`. The `WASM Build + Contract Verification` job
failed at the `emcc` link step with:

```
wasm-ld: error: duplicate symbol: dedx_get_density
>>> defined in /tmp/.../dedx_extra.o
>>> defined in /build/src/libdedx.a(dedx.c.o)
```

The bumped libdedx commit (`feat: expose nucleon number, atom mass, density
and is-gas accessors`, APTG/libdedx#119/#124) promotes four previously
internal helpers to its public API in `include/dedx.h`:

```c
int   dedx_get_nucleon_number(int ion, int *err);
float dedx_get_atom_mass(int ion, int *err);
float dedx_get_density(int material, int *err);
int   dedx_is_gas(int target, int *err);
```

Of these, only `dedx_get_density` collides by name with this repo's own
thin wrapper in `wasm/dedx_extra.c` (the other three libdedx names differ
from the local `dedx_get_ion_nucleon_number` / `dedx_get_ion_atom_mass` /
`dedx_target_is_gas` wrappers, so no collision there).

**Fix**: removed the now-redundant `dedx_get_density` definition and
declaration from `wasm/dedx_extra.c` / `wasm/dedx_extra.h`. The JS-facing
exported symbol name (`_dedx_get_density`) is unchanged — `build.sh` already
listed it in `EXPORTED_FUNCTIONS`, so it now resolves straight from
`libdedx.a` instead of the local wrapper object file. No TypeScript changes
needed (`src/lib/wasm/libdedx.ts` only depends on the exported symbol name).
Verified with a native `gcc -c` compile of `dedx_extra.c` (no Docker/Emscripten
available in this session) and confirmed `pnpm test`, `pnpm lint`,
`pnpm run check`, and `pnpm run format:check` all pass.

Updated `docs/06-wasm-api-contract.md` (§4.4, §4.5, §11) to document that
`dedx_get_density` now comes directly from libdedx's public API rather than
from the local `wasm/dedx_extra.h` wrapper set — this also corrected a
pre-existing stale row that mislabeled `dedx_internal_read_density` as the
function backing `getDensity()`.
